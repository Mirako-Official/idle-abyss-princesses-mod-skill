# hero.js: structure, patterns and pitfalls

The authoritative API is the game's Author Kit (`modkit/docs/MODDING.md` chapters 2–5, 7, 14;
`modkit/docs/HEROES.md`; `modkit/web/heroes/_template.js`; the complete example
`modkit/modding/examples/yoru/hero.js`; types in `modkit/modding/iap.d.ts`). Read those for the field
list of your game version. This file is the experience on top: how to organise a hero that passes the
hero lab, and the traps that do not show up as errors.

## Contents

## 1. How mod scripts run

- Each script in `mod.json` `scripts` is wrapped in a function with one argument, `MOD`. Top-level
  `const` / `function` stay private to that file; share between your files through `MOD.shared`
  (e.g. `art_icons.js` sets `MOD.shared.itemArt`, hero.js reads it).
- Normal scripts run **before the game's own scripts load**. `registerHero`, `IAP` and the data
  helpers exist, but UI and renderer globals (`showModal`, `VFX`, `R` fields…) do not yet. Anything
  that touches them must run later: inside callbacks (cast, update, draw) or in `IAP.onReady(fn)`.
  Example of a silent failure: `if (typeof VFX === 'object') VFX.my_kind = {…}` at the top level
  never runs, because `VFX` is not defined yet.
- A thrown error anywhere revokes the whole mod (it disappears from the picker, the mod manager shows
  the error). Test after every change.
- Code mods need a game restart to pick up changes (developer mode only hot-reloads data packs).

## 2. File layout and the balance table

```
mod/
  mod.json        "api": 3, "scripts": ["art_icons.js", "hero.js", (optional) "ai_chat.js"], "i18n": {...}
  art_icons.js    generated by icons.py
  hero.js         one registerHero({...}) call
  i18n/en.json …  { "Chinese source": "translation" }
  portrait.webp, portraits/, chibi/, preview.jpg, README.md
```
Put every number in one table at the top (`const MH_BAL = { passive: {...}, strike: { coef: 3.2, cd: 6 }, sets: {...}, legends: {...} }`)
and build every description from it (`desc: \`造成 ${pv(MH_BAL.strike.coef * 100)}% 伤害\``). Balancing is
then editing one table, and descriptions never drift from the numbers. The game's display helpers:
`pv(x)` returns a string with one decimal below 10 and a whole number from 10 up (`pv(2.5)` → "2.5",
`pv(1400)` → "1400"); `mulv(x)` writes multipliers with up to two decimals for "×N" texts. Write
percentages as `pv(coef * 100)`.

## 3. Required shape

- Required fields: `id n hero main ele weapons offhands offKind attack weaponStyle icons skills talents`
  (check `_template.js` of your version). `main`: str / dex / int. `ele`: phys fire holy light cold
  poison. `offKind`: shield / orb / quiver.
- Ids: legendary `k` and set `key` must start with `<hero id>_`; skill ids and talent node ids are
  global too, so prefix them (`mh_`). A duplicate id anywhere makes the whole mod fail.
- Talents: exactly 3 trees × 7 nodes, node kinds in order `stat stat pick stat key pick cap`. Use the
  helpers the template uses (`T`, `PICK`, `TAL_KEY`, `CAP`); each tree has `route` and `skills`
  (its three recommended skills). `talAuto` gives the auto-allocation order. Pick options and the cap
  node can use **your own effect flags** (`CAP('mh_t7', 'name', 'mh_overheat', 'what it does')`): the
  flag shows up in `c.FX.mh_overheat` / `R.st.FX.mh_overheat` and you implement the effect yourself.
  You do not need the game's built-in flags, whose effects are mostly undocumented.
- For the hero lab, every route needs a set with **at least 6 pieces** and **two route legendaries in
  different slots** without `minStage`. Without them the route cannot be graded and the Workshop
  balance tag is missing.

## 4. Patterns

**Resource** (a bar under the life bar):
```js
reset(h) { h.rice = 0; },                                   // runtime only, on R.hero, never saved
update(c, dt) { c.h.rice = Math.min(cap, (c.h.rice || 0) + rate * dt); },
onKill(m) { R.hero.rice = Math.min(cap, (R.hero.rice || 0) + (m.boss ? 30 : m.elite ? 12 : 3)); },
resource: (h, st) => ({ v: Math.floor(h.rice || 0), max: cap, c: '#c8a868', label: '白饭' }),
```
The label is white text with a black shadow: choose a saturated mid-tone `c` (orange, red, teal,
gold-beige). A near-white bar makes the label unreadable. Translate the label too (it is built at run
time, so `i18n_dump.js` only sees it while that hero is being played).

**Damage hooks**: `hitMultiplier(m, src, opt)` multiplies every hit the hero (and the hero's pets, `src ===
'pet'`) deals; `hurtMultiplier(h, st)` multiplies damage taken. Keep them cheap: they run on every
hit. Do not read saved data there (`MOD.data.get()` copies JSON); cache a number instead.

**What a hook can see.** `cast(c)` and `update(c, dt)` get a context (`c.h`, `c.st`, `c.FX`, `c.L` …).
Hooks without one (`hitMultiplier`, `hurtMultiplier`, `onKill`, `onBasicHit`, `skillCooldown`, `petHaste` …)
read the live state: `R.st` (current stats), `R.st.FX` (effect flags: set bonuses, talents), `R.st.L`
(worn legendaries, `R.st.L.<id>_ring` is truthy when worn), `R.hero` (the hero at run time). The
argument lists of each hook are in the Author Kit's `docs/HEROES.md` and `iap.d.ts`; when one is not
typed there, copy how the yoru example or an official hero file uses it.

**Skills**: `cast(c)` gets a context with the hero `c.h`, stats `c.st`, effect flags `c.FX`,
legendaries `c.L`, monsters `c.mons`, `c.near(r)`, the skill id `c.id`, screen position `c.sx/c.sy`.
Return `false` when there is nothing to do (no target) so the cooldown is not spent. Deal damage with
`hit(m, coef, kind, opt)`; status with `applyStatus(m, 'freeze' | 'stun' | ..., { t })`.
Skill `mul: k => ...` multiplies that skill's damage in both combat and the panel (use it for 6-piece
set multipliers and legendaries, not a global damage stat).

**Movement (dash, charge, blink; game 3.1.1+)**: never write `HX` / `HY` yourself (the hero
teleports with no movement and move-based effects miss it). Use the skill context:
```js
mh_rush: { n: '突进', lv: 6, cd: 7, desc: `冲向最远的敌人，沿途造成 ${pv(MH_BAL.rush.pass * 100)}% 伤害，到达后再造成 ${pv(MH_BAL.rush.coef * 100)}% 伤害。`,
  cast(c) {
    const far = c.mons.slice().sort((a, b) => Math.hypot(b.gx - c.hx, b.gy - c.hy) - Math.hypot(a.gx - c.hx, a.gy - c.hy))[0];
    if (!far) return false;
    return c.dash(far, { dur: .22, col: '#b48cff',
      pass: m => hit(m, MH_BAL.rush.pass, 'ww', { sk: c.id }),                 // every enemy on the way, once
      end: () => { if (!far.dead) hit(far, MH_BAL.rush.coef, 'ww', { sk: c.id }); } });   // on arrival
  } },
```
- `c.dash(target, opts)`: `target` is a monster (stops 0.9 tiles in front of it, bosses 1.4) or
  `[gx, gy]` in grid tiles (the field is 12×12). Returns `false` when it did not move (too close,
  dead, already dashing): return that from `cast` so the cooldown is not spent.
  Options: `dur` seconds (or `speed` tiles/s, default 18), `stop`, `inv` (invulnerable while
  dashing), `lock: false` (keep attacking and casting; by default the dash locks like a cast),
  `col` (trail colour), `pass(m)` with `width` (default 0.6 tiles), `end()` (not called when the dash
  is interrupted by death, a stage change or entering / leaving a rift or raid).
- `c.blink(target, { stop, col })` teleports with an after-image (what the official heroes' leaps use).
- `c.hx` / `c.hy` are the hero's grid position, `c.dashing` is true during a dash.
- Hooks without a target (`update(c, dt)`, `onKill`, …) use the globals `heroDash(gx, gy, opts)` and
  `heroBlink(gx, gy, col)` with coordinates you compute (`HX` / `HY` are fine to read).
- Enemies are moved by ground zones with `pull` (tiles per second towards the centre; HEROES.md).

**Transformation** (like the Dragon Princess's dragon form; game 3.1.1+): a timed `R.hero` state, the
damage hooks and `sprite.form`. Read `references/transform.md`.

**Cast lock**: `c.h.ww = seconds` stops basic attacks and other skills for that long (wind-up,
channel, a nap). It is deterministic and the panel can model it.

**Delayed hits**: `later(seconds, fn)`; inside, check the fight is still the same one
(`const enc = R.encounter; later(t, () => { if (enc !== R.encounter || R.hero.dead > 0) return; ... })`).
Do not reuse the cast context inside the callback (targets may have died or moved): look things up
again with live helpers, e.g. `targetable(live()).filter(m => hdist(m) < r)` for enemies near the
hero and `iso(HX, HY)` for the hero's screen position.

**Pets**: `addPet(ttl)` for temporary summons, `petCount(K)` for permanent ones (e.g. a 4-piece
bonus), `petLimit`, `petStats`, `petElement`, `drawPet(c, p)` to draw them yourself.

**Randomness**: combat code may use the game's `rnd` / `chance` (they are part of the replayable
combat stream). VFX code must use only `vrnd`, never `Math.random`.

**Floating text over enemies** (jokes, "×2.7"): the game's damage numbers (`R.texts`) are an ASCII
pixel font, so draw Chinese text yourself. Draw it in the VFX "air" layer, which is painted after the
dungeon darkness; text drawn in `drawAura` sits under the darkness and is ~20 % bright away from the
hero. Register the kind once the game is loaded:
```js
function sayKind() {
  if (typeof VFX !== 'object' || !VFX || VFX.mh_say) return;
  VFX.mh_say = { air(c, e, k) {                      // k = 0..1 progress
    let [x, y] = e.m ? iso(e.m.gx, e.m.gy) : iso(HX, HY); y -= (e.m ? 30 : 34) + k * 6;
    c.save(); c.font = '12px "Ember Pixel", sans-serif'; c.textAlign = 'center'; c.globalAlpha = k < .7 ? 1 : (1 - k) / .3;
    const s = TZ(e.s); c.fillStyle = '#0a0e1c'; c.fillText(s, Math.round(x) + 1, Math.round(y) + 1); c.fillStyle = e.c; c.fillText(s, Math.round(x), Math.round(y)); c.restore();
  } };
}
IAP.onReady(sayKind);
function say(s, col, m) { if (R.quiet) return; sayKind(); vfx('mh_say', { s, c: col || '#fff2e0', m: m || null, d: 1.2 }); }
```
`vfx()` returns null with "reduce effects" on or in the widget window; fall back to `drawAura` there
if the jokes matter. `TZ()` translates the text with your i18n entries.

**Skill VFX**: `vfx: { mh_strike: () => { const m = vNear(), at = vAt(m); vfx('arc', { ...at, r: 18, c: '#b070ff', d: .3 }); } }`.
Kinds and parameters, your own kinds, the preview script and pixelfx sprite sheets: `references/skill-vfx.md`.
Designing the skills themselves: `references/skill-design.md`; legendaries and sets: `references/item-effects.md`.

## 5. Panel estimate

`estimate(K)` returns `{ dmg, ehp }` (and optionally `reactive`, extra DPS that only happens when hit)
— positive multipliers the character panel uses for DPS and toughness. It must have no side effects.
`K` holds `L`, `FX`, the stats `a`, `avg` (average hit), `hitMax`, `dps` (basic-attack DPS), `skDps`,
`eff` (panel DPS before your multiplier), `ehp`, `eq` (equipped skill ids), `skCd(id)` (effective
cooldown), `skMul`, `skSpec`, `crit`, `critDmg`; see the Author Kit's HEROES.md for the current list.
The lab compares the panel against measured damage; keep the error within ±20 % (the lab shows it).
Note for pets: when the pet limit is full, `addPet` only refreshes the oldest temporary pet's
timer, so do not count more pets than the limit. Model what your
mechanics do on average: uptime of buffs (duration ÷ cooldown), cast-lock time lost, pets present on
average, resource level on average. If a mechanic multiplies damage in combat (resource bonus, set
×mul through `mul`, a chat bonus), multiply the estimate too.

## 6. Items

- `legends: [{ k: '<id>_x', t: 'weapon', route: 'a', name, desc, fl }]` — two per route, different
  slots. `fl` = flavour line (put the joke there).
- `sets: [{ key: '<id>_set', name, route, pieces: { helm, shoulders, armor, gloves, pants, belt, boots },
  b: [[2, text, stats], [4, text, stats or { fx: '<flag>' }], [6, text, { fx: '<id>_set6' }]] }]` — read
  the 6-piece flag in a skill `mul` or `hitMultiplier`. Avoid stacking a flat global damage stat.
- `court: { setName, pieces: {...}, items: { weapon: { name, power, fx, conds }, offhand, belt, boots } }`
  — MODDING 3.5 lists the `fx` and `conds` the game supports.
- `itemArt: MOD.shared.itemArt` — keys `leg:<k>`, `set:<key>:<slot>`, `court:<slot>`, `skill:<id>`.

## 7. Pitfalls checklist

- [ ] Portraits are 450×720 (not 360×576); no template `portrait.png` left over.
- [ ] `face` set from the real portrait.
- [ ] Nothing touches game UI / renderer globals at the top level of a script.
- [ ] Prefixed ids everywhere; 3 trees × 7 nodes; 6+ set pieces and 2 route legendaries per route.
- [ ] Resource bar colour readable; label translated.
- [ ] Floating Chinese text drawn in the VFX air layer, registered after load.
- [ ] Every description built from the balance table; i18n keys match the rendered sentences
      (`i18n_dump.js`).
- [ ] No `Math.random` in VFX code; no saved-data reads in hit hooks.
- [ ] Dashes and leaps use `c.dash` / `c.blink`, never assignments to `HX` / `HY`.
- [ ] A transforming hero follows the checklist in `references/transform.md`.
- [ ] `mod.json` names ≤ 40 and descriptions ≤ 300 characters per language (the game cuts them).
- [ ] `python scripts/check_mod.py mod` shows no ERROR.
